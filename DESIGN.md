# Design

<!-- impeccable:design-schema 1 -->

## World

**On Air.** Your English gets corrected the moment it happens, cut into like a live broadcast, not filed away in a quiz result. Rooted in the same audience truth as before (Hebrew-speaking learners, children through adults), but replaces the old "Subtitle Culture" direction's quiet, letterboxed cinema-caption look with real spectacle: this is a full redesign-overhaul, explicitly requested by the user ("change everything design-wise, except the logo, and try to build something impressive"), not a refinement of the previous world. Direction contract: `.impeccable/surfaces/src-app-marketing-page-tsx.md`. Seed key `0a1ce211`, assigned candidate #5 of the grounded list (a live broadcast desk).

The old world's letterboxing and translucent glass are gone. In their place: bold, flat color-block fields (never gradients standing in for content, never glass standing in for a plate) and a genuine two-tone studio split behind the hero's headline and its live segment.

**Dark is the first-visit default**, not a system-preference guess — the user asked for it directly, and the world genuinely reads better there (the near-black plates against the saturated color fields carry more of the "broadcast at night" charge than the daylight translation does). `layout.tsx`'s no-flash script now sets `data-theme="dark"` whenever no explicit choice is stored; a stored choice from the toggle still always wins. `manifest.ts` and `viewport.themeColor` were updated to the dark-mode primary/background to match. Light mode is preserved in full and reachable from the same toggle as before — this changes which theme a first-time visitor lands on, not whether light mode exists.

## Palette

**The landing page runs one uniform blue, not two.** The user asked directly: one shade of blue, the same as the Saylo logo, not blue-and-teal. `--accent` (teal) is gone from every `Landing*` component — the English/Hebrew "two channel" color-coding this world started with is retired on this page specifically. The rest of the site (app, admin, the separate pricing/privacy/terms/auth pages, the shared `Navbar`) still uses both `--primary` and `--accent` exactly as before; this change is scoped to the marketing landing page only, per the user's explicit "only the home page."

`--primary` is sampled directly from the real Saylo logo gradient (`public/logo-mark.png` runs blue `#0b7ce5` → teal `#0ab1db`; `--primary` is the blue end) — the logo itself was the one constraint the user pinned ("except the logo"), so the landing page's one color stays recognizably Saylo rather than an invented blue.

| Token | Dark (native) | Light (daylight translation) |
|---|---|---|
| `--background` | `#0b0c0f` | `#faf7f0` |
| `--background-2` | `#17181c` | `#f1ebdf` |
| `--foreground` | `#f3efe4` | `#211c14` |
| `--card` / `--card-border` | `#1c1d22` / `#2e2f36` | `#ffffff` / `#e4dbc8` |
| `--primary` (the landing page's one color) | `#4d9eff` | `#0066d6` |
| `--accent` (teal — used elsewhere on the site, not on the landing page) | `#2dd4cf` | `#00a19d` |
| `--muted` | `#a39c8c` | `#6e6656` (5.3:1 on body) |

**One blue, one intensity — field and button match exactly.** This went through two rounds: full-saturation `--primary` across whole fields read as glaring (user feedback), so a softened `--primary-soft` blend went in for large areas while buttons stayed full-strength; then the user looked at the actual result and asked for the opposite — the field should be the *same* blue as the button sitting on it, not a muted variant, because two intensities of the same hue read as mismatched rather than restrained. `LandingHero`, `LandingFinalCta`, and `LandingTrustStrip` all now use flat `bg-primary` for their fields, matching every button's own `bg-primary`. `--primary-soft` still exists in `globals.css` (`color-mix(in srgb, var(--primary) 45%, var(--background))`) but nothing on the landing page currently uses it — kept for the next surface that wants a genuinely muted field without a same-hue button next to it.

**A same-color button needs a different affordance when nothing separates it from its field.** The hero's primary CTA sits inside the white/dark headline card, so field and button matching is invisible as a problem — the card itself is what separates them. `LandingFinalCta`'s button sits directly on the section field with no card between them; matching its color to the field would have made the button disappear entirely. Inverted instead (`bg-background`/`text-foreground`, the field's opposite pole) as the section's one deliberate punch-through moment, rather than force a same-hue match that breaks affordance.

**A blend ratio that reads safely in one theme can fail in the other** — a real bug caught along the way, worth keeping as a lesson even though the fields it applied to are full-saturation now. `--primary-soft` at 45% measured 5.58:1 for foreground-toned text in dark mode but only 3.73:1 in light mode for the identical class, because the two themes' foreground/background luminance relationship isn't symmetric — a "medium" blend can land in a contrast no-man's-land in at least one theme even when it looks fine in the other. Verified via canvas-composited pixel sampling (not raw `getComputedStyle` colors, which return unparseable `color(srgb ...)` / `oklab(...)` strings for `color-mix` results and opacity-modified colors): hero LIVE flag 5.42-6.79:1, final-CTA heading/body 5.42-6.79:1, ticker 5.42-6.79:1, all across both themes. All comfortably above WCAG AA.

Color strategy on the landing page: **Committed** — the hero, ticker, and final CTA are solid primary fields, not accents scattered on a neutral ground. Operate surfaces (dashboard, exercises, admin) stay **Restrained** as before, with both primary and accent available — this redesign was scoped to the marketing/landing page only.

Never literal news-red. The "breaking" charge comes from Saylo's own logo blue at full saturation, not a borrowed broadcast convention that would clash with the logo and with `--danger`'s existing meaning.

## Type

- `--font-rubik` (Hebrew UI chrome) and `--font-jakarta` (English learning content, via `EnglishText`'s `.font-content` class) are unchanged — both already fit either world.
- New: `--font-chyron` (Anton), an oversized, condensed, all-caps impact face for broadcast-headline moments only — the hero H1, section leads that carry English marketing copy, and the two short English broadcast-convention tags (LIVE, NOW). Declared in `globals.css` *after* `.font-content` so it wins the cascade tie when `EnglishText` applies both classes to one element (a real bug caught during the build: without this ordering, `.font-content`'s `font-family` silently won and Anton never rendered).
- Hebrew section headings get their own impact register without a second typeface: `font-black tracking-tight` on Rubik, not the Anton face (which has no Hebrew glyphs and would silently fall back to an uncontrolled system font). English UI chrome outside the hero stays in short, deliberate broadcast-convention tags (LIVE, NOW) rather than translating full Hebrew headings into English — the site's primary UI language stays Hebrew throughout, exactly as before.
- Retired: the old world's Caveat and IBM Plex Mono are still gone (unrelated to this pass, already retired earlier).
- No gradient text (mechanically enforced — `bg-clip-text` returns nothing).

## Components

- **One uniform blue field** (`LandingHero`, `LandingFinalCta`) — the old two-tone blue/teal studio split is gone along with the accent color; the hero and final CTA are a single `--primary`/`--primary-soft` field. Retired, not just unused: the split panel div was deleted from `LandingHero` entirely rather than left in place rendering the same color as its surroundings.
- **Chyron plate** — a `bg-card` card with a `w-1.5` primary-colored edge bar, `rounded-lg` with `shadow-2xl`, not glass. The one recurring structural device replacing the old caption-bar.
- **`LandingCorrectionDemo`** — same signature-moment mechanism as before (a state machine cycling four real mistakes, typed in via clip-path wipe, struck through, corrected, captioned in Hebrew), re-skinned as a chyron plate instead of a translucent glass card on a dark ground.
- **The one LIVE flag** — a pulsing primary-colored dot plus a small `chyron`-styled "Live" tag, used exactly once in the hero. Never repeated as a HUD element across the page (that repetition was the retired timecode mistake from the previous pass, and the discipline carries forward into this one).
- **The one ticker** (`LandingTrustStrip`) — a real scrolling news ticker, ` design-taste-frontend`'s one marquee-per-page allowance spent on the single place a marquee is this world's own thesis rather than a decorative reach. A `chyron`-styled "Now" tag anchors a `w-max` duplicated-content track animating `translateX(-50%)` for a seamless right-to-left loop, which reads correctly for RTL content (new text enters from the right, matching how Hebrew is already read).
- **Segment rundown** (`LandingSteps`) — a numbered list, not a card grid. Numbers are earned here, unlike the old direction's banned 01/02/03: a real broadcast rundown genuinely is numbered order, so the segment numbers (large, `chyron`, low-contrast `text-card-border`) carry real information rather than decoration.
- **Signal meter** (`LandingFeatures`) — a small five-bar ballistic level meter, raised from the VU-meter-bridge challenger (competitive verdict: it beat the assigned direction on product clarity for anything genuinely audio). Used exactly once, next to the voice-call feature only, because that is the one feature that is actually audio — not a generic "live" flourish reused on every card.
- **Studio breathing wash** (`LandingHero`) — a slow, quiet animated radial glow over the hero field, raised from the shader-portal challenger's full-bleed commitment (declined verdict overall — a literal WebGL shader and custom cursor would be generic tech spectacle unrelated to the product — but its ambition donated this one restrained touch: the ground is never perfectly flat and static).
- **Buttons and cards** — `rounded-lg` throughout (not the old world's full pills), a deliberate shape-system change: broadcast graphics are crisp rectangular plates, not soft video-player pills.

## Refused (mechanically checked by `impeccable detect`)

Same-size icon+heading+text card grids, the hero-metric template, kicker/eyebrow labels (except where a rundown's own segment numbers are earned, see above), decorative blur/glass (the correction demo and pricing card are now solid plates, not frosted panes), gradient text, hard neobrutalist shadows, monospace-as-costume, emoji-as-icon, literal news-red. See `craft-floor.md` for the full list.

## Scope of this pass

Built and finish-reviewed: the marketing/landing page (`Landing*` components), the global `Navbar` (a lighter touch there — a bolder wordmark weight and a 2px accent bottom rule, since the navbar is persistent chrome across both Persuade and Operate surfaces and stays closer to Restrained even while the page content underneath goes bold), and the full auth funnel (`LoginForm`, `/signup`, `/reset-password`, `/reset-password/confirm`) — the pages every hero CTA actually lands on, previously bare unstyled inputs with no connection to the site's identity. Each now wraps its form in the same plate language as the rest of the site (`bg-card` panel, primary-colored top edge, `rounded-lg` inputs and buttons replacing the old `rounded-xl`), and `/signup`'s submit button — the one truly "start" action on these pages — carries the same press-play `Play` icon as the hero's own primary CTA.

Not restructured in this pass, deliberately: the authenticated app (dashboard, exercises, games, profile, admin) was already rebuilt as its own disciplined Operate surface in the previous pass (see git history) and inherits this pass's corrected color usage automatically through the same CSS custom properties — it does not inherit the hero-specific devices (color-block splits, the chyron face, the ticker, the LIVE flag), which stay scoped to the Persuade surfaces where design-taste-frontend and craft-floor.md both say expression belongs.

**Shape consistency, extended app-wide.** `rounded-2xl` (the pre-"On Air" card radius) was still sitting in 45 files across the whole codebase — dashboard, every exercise page, admin, shared components like `ContentCard` (which alone drives the card grid on vocabulary/grammar/reading/listening/writing/idioms/learn). Swapped to `rounded-lg` everywhere, matching the radius the landing page and auth funnel already committed to. The dashboard's greeting card also picked up the same primary-colored top edge every other plate on the site now carries (hero, correction demo, pricing teaser, the auth forms) — one recurring detail reused, not invented per surface.

A second, larger pass then found the same fault one radius step up: every button, text input, and feedback panel across the entire exercise/game/test ecosystem (`ExercisePlayer`, `McqQuestion`, `MatchQuestion`, `ReorderQuestion`, `DictationQuestion`, `FillBlankQuestion`, `VocabTest`, `ReadingExam`, `SpeakingTest`, all ten `/games/*` pages, `placement`, `review`, the writing/reading response forms, the speaking chat composer, profile forms, auth-adjacent `ConsentRequestForm`/`ConsentDecision`) was still on `rounded-xl` — the old world's control radius, never touched by the first sweep because it targeted card radii, not control radii. Converted ~43 files to `rounded-lg`, leaving `rounded-xl` only where it was never the inconsistency: the small icon-badge circles (`w-8`-`w-12` containers) and the two concentric nav-pill wrappers (`Navbar`, admin layout, progress-page segment control) whose outer radius is deliberately one step larger than the `rounded-lg` tab buttons nested inside them. This is the surface the user actually touches most — every exercise answer, every game round — so it's the one where a stray radius was most visible.

**Answer feedback, made legible without relying on color alone.** Every multiple-choice question in the app — `McqQuestion`, `VocabTest`'s inline MCQ step, and five duplicated MCQ renderers across `idioms/practice` and four `/games/*` pages — marked a correct or wrong option with border and background color only, no icon, unlike `MatchQuestion`'s own matched-pair state, which already carried a small `Check`. Added the same `CheckCircle2`/`XCircle` language to every one of those seven, on the option itself once it's answered: a full green ring for the right answer, a red one on whatever was actually picked if it was wrong. This is a real accessibility fix, not decoration — color-only correct/incorrect state fails users with color-vision deficiencies, and CVD is common enough that a game/quiz surface used by a general audience shouldn't rely on it alone. Verified the icon lands on the reading-direction "end" side in the app's RTL layout (not crowding the Hebrew/English option text) via a direct DOM measurement, not by eye.

Verification performed: `tsc`/`eslint` clean, `impeccable detect --json` returned no findings on every changed file, the full test suite (82/82) and production build both pass. Contrast measured directly via computed styles in both themes (not estimated) — see Palette above for the numbers. Checked at mobile (375px, no horizontal overflow, no clipped text) and desktop, both themes. No named finish-reviewer or documenter subagent was available in this environment; this document and the verification above were produced in-thread as the disclosed substitution.

**Honest risk.** This is a genuine departure from the previous, more restrained direction, adopted at the user's own explicit request after two rounds of them asking for more visual ambition. It trades some of the previous world's quiet sophistication for real graphic energy. The user was told before building that this could be reverted with git if it doesn't land, and every step of this pass is its own commit for exactly that reason.
